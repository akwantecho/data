# ADR-0005: AI is an explanation layer with no write access

- **Status**: Accepted (Sprint 0, enforced from Sprint 9)

## Context

The product is a decision-support system. Numbers shown to management must be
reproducible and defensible. A model that computes or invents figures destroys
that guarantee, and the failure is invisible: wrong numbers look exactly like right
ones.

## Decision

The AI layer is downstream of the analytics engine and read-only:

```text
Database → Analytics Engine → Verified KPIs → Insight Context → AI → Explanation
```

Boundaries fixed now, before any AI code exists:

1. The model receives a **structured context object** built by the backend
   (organization, industry, period, verified metrics and changes, targets, alerts,
   insights, goals, health scores, data quality) — never raw tables, never SQL.
2. The model has **no write path**. No tool, endpoint or service lets it modify
   metrics, values, goals or decisions.
3. Insights and alerts are generated by deterministic rules. The AI explains them;
   it does not detect them.
4. Answers must cite metric names and periods, distinguish facts from
   interpretation, disclose missing or low-quality data, and prefer "may indicate"
   over asserted causation.
5. `ai_queries.context_summary` persists the context that produced an answer, so any
   statement can be reproduced and audited. Provider internals are not stored.

The provider sits behind a service abstraction so it can be swapped or disabled;
when it is unavailable the platform degrades to its deterministic output rather
than failing.

## Consequences

- Every number in an AI answer exists in the database beforehand and can be traced.
- AI quality is bounded by the analytics engine — which is the correct dependency
  order for a system whose value is trust.
- Answers cost one context build per query; the context builder is therefore shared
  with the dashboard aggregation rather than written twice.
